Host Configuration Script Library

Build any new lab machine to the same standard with one paste. Serving from 192.168.1.195.

Pick your distro, paste into a terminal on the new machine. Not sudo — the script escalates on its own.

Ubuntu / Debian

Two steps recommended

Leaves the scripts on the box. Every script is idempotent, so re-running is the normal way to repair a host.

wget http://HOST/ubuntu/host_setup.sh
bash host_setup.sh

One line

Runs in a throwaway directory, so it leaves nothing behind.

cd "$(mktemp -d)" && wget -q http://HOST/ubuntu/host_setup.sh && bash host_setup.sh

Fedora

Two steps recommended

curl, not wget: a stock Fedora Workstation has no wget, so the Ubuntu line fails at the very first command. wget arrives later, during the desktop step.

curl -fsSLO http://HOST/fedora/host_setup.sh
bash host_setup.sh

One line

cd "$(mktemp -d)" && curl -fsSLO http://HOST/fedora/host_setup.sh && bash host_setup.sh

Options

--no-nas
Skip the NAS mount entirely. Required on a DMZ or prod-local host: the network design forbids it reaching the NAS, and a uniform build would otherwise plant NAS credentials on a machine that can never use them.
--hostname <name>
Set the static hostname. Available on both distros since Aug 21, 2026. It also fixes the matching /etc/hosts entry — which hostnamectl does not touch, and whose absence makes every later sudo print unable to resolve host — and pins the name so cloud-init cannot revert it at the next reboot. Needed on Fedora because ISO installs inherit localhost-live from the installer; needed on Ubuntu for renames and for hosts installed from an ISO rather than cloned.
--server
Both distros since Aug 21, 2026. Headless host: skips Google Chrome (~431 MB) and Cursor (~1012 MB), plus the resolution, dock, terminal-profile, keyring and autologin steps. Still installs the CLI tools and shell aliases, which matter more on a server than on a desktop — and on Fedora it still masks the systemd sleep targets, which a server needs more than a desktop does, since nobody is sitting in front of it to wake it up. Usually unnecessary — the build auto-detects a headless host and does this on its own. The flag is for forcing server treatment on a machine that has a desktop.
-h, --help
Print the usage and exit without touching anything.

The script downloads its sub-scripts, shows you what it got, and asks once before changing anything.

Do not pipe this into bash

⚠ curl … | bash is broken for this script

It is the usual idiom and it is the one form that does not work here. Both shortcuts fail, and both were measured rather than assumed:

  1. curl … | bash — the script arrives on stdin, so the confirmation prompt's read consumes the next byte of the script itself. Observed: the reply came back as e, taken from the following echo; the run aborted, and bash then reported cho: command not found because the line had been eaten.
  2. bash <(curl … ) — host_setup.sh downloads its sub-scripts next to itself, using dirname "${BASH_SOURCE[0]}". Under process substitution that resolves to /dev/fd, which is not writable, so every download fails.

Downloading to a real file fixes both. That is all the one-liners above are doing.

Browse the scripts

/ubuntu/
Ubuntu & Debian build standard. Download individual scripts by hand.
/fedora/
Fedora build standard. Same layout, dnf instead of apt.
Each tree has one host_setup.sh orchestrator plus the per-concern scripts it calls — hostname, SSH, sudo, Cockpit, Docker, the NAS mount and the desktop. Any of them can be run on its own. Editing a script here publishes it immediately; nginx serves the directory straight off disk. A machine you already built keeps whatever it downloaded at build time, so a change here affects future builds only.
